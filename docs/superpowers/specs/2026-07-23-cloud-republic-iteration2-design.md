范围：难度系统、文明式回合流、全量双语、性能定点优化、README

## 1. 背景

第一轮已完成单文件重构与机制修复（61/61 断言绿，贪心 bot 胜率 0.4%）。本轮五项需求已与用户逐项确认：

- 胜率提升 → **多档难度可选**（用户拍板）
- 中英文切换 → **全量双语**（界面/卡牌/事件/日志/规则/结局）
- 「改为回合制」→ **文明系列/Humankind 式回合流**：玩家回合内自由行动，点 Next Turn 推进，无自动计时（用户明确）
- 项目结构 → **只加 i18n.js + README**，不拆 ui.js、不引构建工具（用户拍板）
- 性能 → **定点优化已知热点**（星空 DOM、手牌全量重渲染）

## 2. 难度系统

- 启动进入开始界面：简单 / 中等 / 困难三个按钮，点击后才 `initGame(difficulty)`。
- 难度配置表 `DIFFICULTY_LEVELS` 放 `data.js`；`createInitialState(difficultyKey)` 接收难度键，默认中等。
- 可调参数：初始资源、maxTurns、corrosionRate、起始手牌数等；**具体数值以实现期模拟调参为准**。
- 验收标准（贪心 bot 各 500 局模拟胜率）：简单 60–80%、中等 30–50%、困难 10–20%。中等以当前数值为基线微调。
- 结算/结局画面显示本局难度。
- **保底机制（2026-07-23 用户拍板，计划调参时发现必要）**：三档均 `guaranteedCards: [12]`——开局手牌必含卡 12（净化引擎卡），否则仅靠资源/回合/腐蚀旋钮数学上无法达到胜率区间。另将 handLimit / drawPerTurn / energyMaintenance 参数化入难度配置。
- 调参干跑实测（种子 1–500）：easy 67.4%、medium 39.8%、hard 15.8%。

## 3. 文明式回合流（方案 A：事件驱动）

- **删除全部 setTimeout 自动推进**（1s / 0.5s / 1.5s 三处）。
- 回合开始：掷事件 → 事件弹窗由玩家自行点击关闭（不自动跳阶段）。
- 玩家回合：出牌（上限 2 → **3** 张）、修理、建造栖息地，**任意顺序任意组合**；移除 turnBlocker 锁区机制。
- 「Next Turn / 下一回合」按钮触发 endTurn 结算 → 结算结果写入日志并停在摘要状态 → 玩家点「开始回合 N+1」继续。
- 罢工回合保持原规则（只能修理/结束回合，含 buildHabitat 的 strike 拦截）。
- 阶段指示器简化保留；胜/负结局流程不变。
- engine 改动仅限：`maxCardsPerTurn: 3`、难度入参、日志键值化（见 §4）。

## 4. 全量双语（i18n）

- 新建 `js/i18n.js`：`CR.i18n = { lang, t(key, params), setLang(lang) }`；字典含全部界面文案、日志模板、规则、结局文案中英条目。
- 静态界面文本：HTML 元素加 `data-i18n="key"`，`setLang` 批量替换；带占位符的用 `data-i18n-params` 或 JS 渲染。
- 卡牌：`data.js` 每张卡加 `name_zh` / `effect_zh`；事件加 `name_zh` / `desc_zh`（66 + 20 条）。渲染按当前语言取字段。
- 日志：`engine.log` 由字符串改为 `log(key, params)`，ui 层经 i18n 模板渲染。约 40 处调用点机械替换。simulate.js 断言同步适配（日志不再断言具体字符串，或断言 key）。
- 语言切换：header 常驻「中文 / EN」按钮，即时重渲染当前界面；存 `localStorage`，默认 `zh`。
- 加载顺序：data → i18n → state → engine → ui。
- 新 UI 文案（难度选择、Next Turn、开始回合等）直接双语入字典。

## 5. 性能定点优化

- 星空：100 个 `.star` DOM 节点 → 单个 div + 多组 box-shadow（一次生成随机位置字符串）。首屏 DOM 节点数 −99。
- 手牌渲染：`renderHand` 加脏标记——仅手牌内容/可打出状态变化时重建；选中切换只改 class，不重建。
- 验收：报告中给出优化前后首屏 DOM 节点数对比；全部断言不回归。
